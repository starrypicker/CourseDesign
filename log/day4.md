## 二、尹领航 —— 后端修复与增强

### 2.1 订单并发问题深入修复

测试版第一版中，订单创建加的是按商品编码的分布式锁，但实际测试发现一个场景有问题：

**场景**：顾客下单 3 个商品（P001 × 2, P002 × 1），同时对 P001 加锁成功，但对 P002 加锁时超时了。此时 P001 的锁已释放但还没回滚，可能导致数据不一致。

**解决方案**：在 `OrderServiceImpl.create()` 方法上加 `@Transactional`，锁内先扣库存、再创建订单。如果中间任何一步失败，整个事务回滚，锁释放后库存恢复。

```java
@Transactional(rollbackFor = Exception.class)
public Orders create(OrderCreateDTO dto) {
    // 按商品编码排序加锁 → 检查库存 → 扣减库存 → 创建订单 → 创建订单细则
}
```

### 2.2 订单超时自动取消优化

原来的 `OrderTimeoutTask` 只是简单地取消超过 24 小时的待确认订单。优化后：

- 取消订单的同时恢复库存
- 记录取消原因到 `remark` 字段："系统自动取消：超过24小时未确认"
- 添加了详细日志，记录取消了哪些订单号

### 2.3 库存预警任务增强

`StockMonitorTask` 原来只是打印日志。增强后：

- 检查所有上架商品中库存低于 `min_stock` 的
- 自动输出预警报告到业务日志文件 `sports-sales-biz.log`
- 标记为需要补货，前端仪表盘可以看到预警列表

### 2.4 进货确认逻辑修复

发现一个问题：如果在进货确认的同时，另一个线程也在操作同一商品的库存（比如订单扣库存），会出现数据不一致。

**修复方案**：
- 进货确认时对商品编码加 Redisson 锁
- `confirmPurchase()` 方法加 `@Transactional`
- 先更新 `purchase_record.status = 1`，再 `UPDATE product SET stock_quantity = stock_quantity + ?`

### 2.5 顾客删除检查完善

顾客删除前要检查关联数据，原来只检查了订单表。完善后检查三张表：

- `orders`：有订单记录 → 不能删除
- `sys_user`：有关联用户 → 同时删除用户记录
- 没有关联的 → 允许删除

### 2.6 数据加密范围扩展

原来的 AES 加密只覆盖了 `customer.phone` 和 `customer.email`。发现订单中的 `recipient_phone`（收件人电话）也属于个人敏感信息，把它也纳入加密范围：存入时加密、读取时解密。

修改了 `OrderServiceImpl` 中所有涉及 `recipient_phone` 的地方，并且更新了 `OrderMapper.xml` 中对应字段的类型映射。

### 2.7 新增 API：订单报表接口

为了前端仪表盘能展示销售数据，新增了几个聚合查询：

- `GET /api/order/report/monthly` — 本月销售额、订单数、商品销量排行
- 在 `OrderMapper.xml` 中新增了聚合 SQL：

```sql
SELECT SUM(total_amount) AS monthly_sales, COUNT(*) AS order_count
FROM orders
WHERE order_status != 3
  AND MONTH(order_date) = MONTH(CURRENT_DATE)
```

### 2.8 分页参数默认值

前端有时不传 `page` 和 `pageSize` 参数，后端会抛出 `NullPointerException`。给所有分页方法加了默认值：

```java
int page = dto.getPage() != null ? dto.getPage() : 1;
int pageSize = dto.getPageSize() != null ? dto.getPageSize() : 10;
```

同时限制了 `pageSize` 最大值为 100，防止恶意请求一次性拉取全部数据导致内存溢出。

### 2.9 日志配置优化

配置了 Logback 三通道日志（`logback-spring.xml`）：

| 日志文件 | 内容 | 滚动策略 |
|----------|------|----------|
| `sports-sales.log` | 全量日志（DEBUG级别以上） | 按天滚动，保留30天 |
| `sports-sales-error.log` | 错误日志（ERROR级别） | 按天滚动，保留30天 |
| `sports-sales-biz.log` | 业务日志（INFO级别，仅 com.sports.sales 包） | 按天滚动，保留30天 |

三通道分离的好处：日常排查看业务日志就够了，出问题时再查错误日志和全量日志。

### 2.10 HTTPS 配置（准备工作）

虽然开发阶段用 HTTP 就够了，但为了后续部署到服务器做准备，添加了：

- `HttpsConfig.java` — SSL 配置
- `KeyStoreGenerator.java` — 自签名证书生成工具
- `keystore.p12` — 证书文件

本地开发通过 `application.yml` 中的 `server.ssl.enabled: false` 关闭了 HTTPS。

## 三、欧行 —— 前端 Bug 修复与功能增强

### 3.1 购物车 Bug 修复

**Bug 1**：购物车中商品数量减少到 0 时没有自动移除。

**修复**：在 `store/index.js` 的 `updateCartQuantity` mutation 中加了判断，如果数量 ≤ 0 则从购物车中移除该商品。

**Bug 2**：购物车商品全选/取消全选状态与表格不一致。

**修复**：`el-table` 的 `@selection-change` 事件中更新 `allSelected` 状态。

**Bug 3**：购物车为空时点击"结算"按钮没有提示。

**修复**：结算前先判断购物车是否有选中商品，为空时弹出提示"请选择要结算的商品"。

### 3.2 订单页面改进

**功能增强 1**：订单详情展开

- 原来订单列表只显示订单总信息
- 现在点击订单行可以展开显示商品明细（调 `orderApi.getDetail()` 获取订单细则）
- 使用 `el-table` 的 `expand` 插槽实现

**功能增强 2**：订单状态流转可视化

- 以前只显示一个状态文字
- 改用 `el-steps`（步骤条）展示订单流程：待确认 → 已确认 → 已付款 → 已发货 → 已签收 → 已完成
- 当前所处的步骤高亮，已完成的步骤打勾

**Bug 修复**：付款后页面没有自动刷新订单状态

- 在付款成功回调中调 `loadOrders()` 重新拉取订单列表

### 3.3 管理员后台改进

#### 3.3.1 Dashboard 仪表盘增强

**原来的 Dashboard** 只简单显示数字，看起来比较空。

**改进后**：
- 统计卡片加图标和渐变色背景（使用 Element Plus Icon）
- 增加了"库存预警商品数"卡片，红色高亮
- 添加近7日销售趋势图（用简单的 CSS 柱状图实现，没有引入 ECharts 以免依赖太重）
- 底部"最近订单"表格只显示最新的 10 条

#### 3.3.2 商品管理增强

**功能增强 1**：商品表格中的库存列根据库存量显示不同颜色
- 库存 > 最低库存 × 3：绿色
- 最低库存 < 库存 ≤ 最低库存 × 3：橙色（警告）
- 库存 ≤ 最低库存：红色（严重不足）

**功能增强 2**：商品图片展示
- 虽然该项目没有实际图片存储，但加了一个根据商品名称生成的渐变色占位图，让表格看起来不单调

**Bug 修复**：编辑商品时单价输入框没做数字校验，可以输入字母
- 给 `el-input` 加了 `type="number"` 限制

#### 3.3.3 订单管理增强

**功能增强**：操作确认对话框

- 原来点击"取消订单"直接调用 API，容易误操作
- 改为弹出确认对话框，告知操作结果（取消后会恢复库存等）
- 发货操作弹窗中预填运输要求，提供常用选项（顺丰速运、京东物流等）

**Bug 修复**：
- 发货日期选择器限制只能选今天及以后的日期
- 已取消/已完成的订单不再显示任何操作按钮

#### 3.3.4 进货管理增强

**功能增强**：
- 新增进货记录时，商品编码和厂家编码改用下拉选择（从后端拉取列表），而不是手动输入编码，减少输入错误
- 确认入库时弹窗确认"确认入库后将增加商品 [商品名] 的库存 [数量] 件"，防止误操作
- 已入库记录的操作按钮灰化，不可重复操作

### 3.4 全局体验优化

#### 3.4.1 Loading 状态

在 `utils/request.js` 的请求拦截器中加入了全局 Loading：
- 请求发送时显示顶部进度条
- 响应回来时隐藏
- 避免页面"卡住"用户不知道发生了什么

#### 3.4.2 错误提示统一

所有接口调用的 catch 块中统一用 `ElMessage.error()` 显示错误信息：
```javascript
try {
  await productApi.add(formData)
  ElMessage.success('添加成功')
} catch (error) {
  ElMessage.error(error.message || '添加失败')
}
```

#### 3.4.3 空状态处理

- 商品列表为空 → 显示 `el-empty` 组件："暂无商品"
- 搜索无结果 → "未找到匹配的商品，请调整搜索条件"
- 订单列表为空 → "暂无订单，快去选购吧" + 跳转按钮
- 购物车为空 → 购物车图标 + "购物车是空的"

#### 3.4.4 表格响应式

部分表格列太多，在窄屏幕上会溢出。加了 `el-table-column` 的 `min-width` 属性和横向滚动。

### 3.5 路由守卫完善

原来的路由守卫只做了简单的登录判断。完善后：

- 未登录访问任何需要登录的页面 → 跳转登录页，登录后自动跳回原页面
- 顾客角色访问 `/admin/*` → 跳转到首页 + 提示"无权限访问"
- 管理员角色访问普通前台页面 → 正常显示（管理员也可以模拟顾客视角）
- Token 过期 → 清除登录状态 + 跳转登录页 + 提示"登录已过期"

## 四、前后端协作修复的问题

### 4.1 参数命名统一

- 前后端都统一用 camelCase（驼峰命名）：`productCode`、`customerCode`、`manufacturerCode`
- 后端 application.yml 中配置了 `mybatis.configuration.map-underscore-to-camel-case: true`，数据库下划线字段自动映射到驼峰

### 4.2 时间格式统一

- 后端返回的时间统一为 `yyyy-MM-dd HH:mm:ss` 字符串格式
- 在 `application.yml` 中配置：`spring.jackson.date-format: yyyy-MM-dd HH:mm:ss`

### 4.3 金额精度

- 后端金额字段用 `BigDecimal`
- 前端显示时统一格式化为两位小数（`toFixed(2)`）
- 前端提交金额时也保持两位小数精度
