## 二、尹领航 —— 后端接口全面测试与修复

### 2.1 接口自测

用 Postman 逐个测试昨天写的所有 API 接口，按模块逐一验证：

**认证模块**：
- `POST /api/auth/login` — 管理员登录（admin/123456）、顾客登录（sun/123456），都能正常返回 Token
- `POST /api/auth/register` — 注册新顾客，自动创建 customer 记录和 sys_user 记录，测试通过

**商品模块**：
- 列表查询、按厂家筛选、按名称搜索、价格区间筛选 → 分页正常
- 添加商品时关联的厂家编码不存在 → 返回友好错误信息（而不是数据库外键报错）
- 修改商品后 Redis 缓存自动清除 → 再次查询获取到最新数据

**订单模块**（重点测试）：
- 创建订单 → 订单创建成功，库存正确扣减
- 同一商品被多人同时下单 → 分布式锁生效，没有超卖
- 确认订单 → 状态从 0 变为 1
- 付款 → payment_status 变为 1
- 发货 → shipping_status 变为 1
- 取消订单 → 库存自动回滚，order_status 变为 3
- 已取消的订单不能再次确认/付款 → 返回"订单已取消"错误

**顾客模块**：
- 手机号和邮箱在数据库中存的是密文（AES 加密）
- 接口返回时自动解密为明文 → 对前端完全透明
- 删除有订单关联的顾客 → 返回"存在关联订单，无法删除"错误

**进货模块**：
- 添加进货记录 → status 为 0（待入库）
- 确认入库 → status 变为 1（已入库），同时 product.stock_quantity 增加
- 重复确认同一入库单 → 分布式锁阻止，返回"该记录已入库"

### 2.2 发现并修复的问题

在自测中发现了几个问题：

1. **订单创建时库存扣减没有在事务里加锁** → 锁加在 Service 方法上，但事务在 Service 方法结束后才提交。改为先在 Controller 层排序商品列表，传给 Service，Service 内部先加锁再操作数据库。

2. **顾客登录后只能看自己的订单** → 在 OrderController 中判断角色：`admin` 可以看全部订单，`customer` 只能用 `customer_code` 过滤自己的订单。

3. **分页参数问题** → 前端传 `page` 和 `pageSize`，后端 SQL 需要 `LIMIT offset, pageSize`，在 Service 层做了转换 `offset = (page - 1) * pageSize`。

4. **CORS 跨域问题** → 添加了 `CorsConfig`，允许前端 `localhost:5173` 的跨域请求。

5. **异常信息暴露过多** → 全局异常处理中把 `e.getMessage()` 返回给前端，有些异常信息包含了 SQL 语句。改为生产环境只返回"系统异常"，开发环境才返回详细信息。

### 2.3 数据库测试数据调整

原来的测试数据只有 4 个厂家、8 个商品、3 个顾客，回传给前端的列表太短看不出分页效果，补充了一些测试数据。

## 三、欧行 —— 前端业务页面开发

### 3.1 顾客前台页面

#### 3.1.1 首页（Home.vue）

- 轮播横幅（展示体育用品促销主题）
- 热门商品推荐卡片（取库存充足、销量好的商品）
- 快捷入口：浏览商品、查看订单

**思路**：首页要简洁大气，一眼能看出系统是做什么的。用 Element Plus 的 `el-carousel` 做轮播，`el-card` 做商品卡片。

#### 3.1.2 商品列表（Products.vue）

这是顾客前台最核心的页面。

- **搜索栏**：商品名称输入框 + 厂家下拉选择 + 价格区间 + 搜索/重置按钮
- **商品卡片网格**：每个卡片显示商品图片（暂用占位图）、名称、价格、库存、厂家，右下角有"加入购物车"按钮
- **分页器**：底部 `el-pagination`，支持切换每页条数

**开发思路**：
- 页面加载时调 `productApi.list()` 获取初始数据
- 搜索条件变化时重新请求，带筛选参数
- "加入购物车"按钮点击后触发 Vuex 的 `addToCart` mutation
- 如果购物车已有该商品，数量 +1；没有则新增

#### 3.1.3 购物车（Cart.vue）

- 表格展示：商品名称、单价、数量（可增减）、小计
- 全选/单选、删除选中
- 底部：合计金额、结算按钮
- 结算前弹窗填写收件信息（收件人、地址、电话）

**开发思路**：
- 购物车数据存在 Vuex store 中，不用每次调接口
- 数量增减和删除直接操作 store
- 点击"结算"时调 `orderApi.create()`，传入购物车商品列表和收件信息
- 创建成功后清空购物车，提示"下单成功"

#### 3.1.4 我的订单（Orders.vue）

- 表格展示：订单号、下单时间、总金额、订单状态、操作按钮
- 状态筛选标签：全部、待确认、已确认、已完成、已取消
- 操作：付款（待确认的订单）、确认收货（已发货的订单）、查看详情
- 点击订单号展开订单明细（商品列表）

**开发思路**：
- 每个状态用一个 Tag 颜色区分：待确认=灰色、已确认=蓝色、已完成=绿色、已取消=红色
- 只显示当前登录顾客自己的订单（后端已经做了权限过滤）
- 付款和确认收货调用对应的 API

#### 3.1.5 个人中心（Profile.vue）

- 展示个人信息（名称、联系人、地址、电话、邮箱）
- 编辑个人信息
- 修改密码

### 3.3 前后端联调

今天最关键的一步：让前端真正调通后端接口。

**联调过程**：

1. 先启动后端（端口 8080），再启动前端（端口 5173）
2. 打开登录页 → 输入 admin/123456 → 点击登录 → 浏览器 Console 报错 `Network Error`
3. 发现问题：Vite 的代理没配置好，前端请求 `/api/auth/login` 没有被代理到 `localhost:8080`
4. 修改 `vite.config.js`：
   ```javascript
   server: {
     port: 5173,
     proxy: {
       '/api': {
         target: 'http://localhost:8080',
         changeOrigin: true
       }
     }
   }
   ```
5. 重新启动前端 → 登录成功！拿到了 Token 和用户信息
6. 接下来逐个接口联调，修复了几个前后端参数名对不上的问题（如后端用 `customerCode` 驼峰，前端用 `customer_code` 下划线，统一改成了驼峰命名）

### 3.4 联调中发现并修复的问题

1. **Axios 响应拦截器把 Result 的 code 判断错误** → 后端成功返回 `code: 200`，前端判断 `res.code === 0`，永远不会成功。改为判断 `res.code === 200`。

2. **登录后 Token 没有及时写入后续请求** → 在登录成功后直接调 `store.commit('setToken', token)`，同时存到 localStorage。

3. **Vuex 持久化** → 页面刷新后 Vuex 数据丢失，Token 和 userInfo 从 localStorage 恢复。

4. **Element Plus 中文配置** → 页面上的分页器、日期选择器都显示英文，需要引入中文语言包并配置 `el-config-provider`。
