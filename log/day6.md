### 2.3 线程池配置

给定时任务加了线程池配置 `ThreadPoolConfig.java`：

```java
@Bean("taskExecutor")
public Executor taskExecutor() {
    ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
    executor.setCorePoolSize(2);
    executor.setMaxPoolSize(5);
    executor.setQueueCapacity(50);
    executor.setThreadNamePrefix("sports-task-");
    executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
    return executor;
}
```

定时任务的 `@Async` 注解指定使用该线程池，避免使用默认线程池导致线程堆积。

### 2.4 敏感配置外部化

安全性考虑：`application.yml` 中的数据库密码、JWT 密钥、AES 加密密钥等敏感信息不应硬编码在代码里（尤其是要提交到 Git 仓库的代码）。改为通过环境变量注入：

```yaml
spring:
  datasource:
    password: ${DB_PASSWORD:123456}
  redis:
    host: ${REDIS_HOST:localhost}
    port: ${REDIS_PORT:6379}

jwt:
  secret: ${JWT_SECRET:sports-sales-jwt-secret-key-2026}

crypto:
  aes-key: ${AES_KEY:sports-sales-aes-key-2026}
```

格式 `${环境变量:默认值}`：有环境变量就用环境变量，没有就用默认值（适合本地开发）。

同时更新了 `README.md` 和 `DEPLOY.md` 中的部署说明，告知用户如何设置这些环境变量。

### 6.3 技术亮点回顾

| 序号 | 技术点 | 应用位置 | 说明 |
|------|--------|----------|------|
| 1 | **分布式锁**（Redisson） | 订单创建、进货确认、退换货 | 按商品编码排序加锁，防死锁，防超卖 |
| 2 | **AES 数据加密** | 顾客电话/邮箱、收件人电话 | 敏感个人信息密文存储，前后端透明加解密 |
| 3 | **JWT + 权限隔离** | 全局拦截器 | 管理员和顾客权限分离，顾客只能看自己的数据 |
| 4 | **Redis 缓存** | 商品/顾客/订单查询 | `@Cacheable/@CacheEvict`，更新时自动清除 |
| 5 | **WebSocket 实时通信** | 客服聊天 | 全双工通信，JWT 握手认证，消息持久化 |
| 6 | **定时任务** | 库存预警 + 订单超时 | `@Async` + 线程池，异步执行不阻塞主线程 |
| 7 | **事务管理** | 订单/进货/退换货 | `@Transactional`，异常自动回滚 |
| 8 | **HTTPS 支持** | SSL 证书配置 | 生产环境安全通信（开发环境可关闭） |
| 9 | **Logback 三通道日志** | 全量/错误/业务 | 按天滚动保留 30 天，问题排查方便 |
| 10 | **统一异常处理** | `@RestControllerAdvice` | 友好错误提示，不暴露内部信息 |

### 6.5 经验与体会

**尹领航（后端）**：
- 数据库设计阶段多花时间思考是值得的，好的表结构让后续开发顺利很多
- 并发问题不能等出 Bug 再修，要在设计阶段就考虑好锁策略
- AES 加密对前端透明是一个好的设计选择，前端不用关心加密细节
- 异常处理不是"兜底"的，应该从第一天就做好，否则排查问题很痛苦
- WebSocket 的握手认证需要额外处理，不能直接复用 HTTP 拦截器
- 退换货和发票的互斥逻辑要在设计阶段就考虑清楚，后期补救很麻烦

**欧行（前端）**：
- Element Plus 组件库确实省了很多时间，表单、表格、弹窗都是现成的
- 前后端联调时参数命名要提前约定好（驼峰 vs 下划线），不然改起来很麻烦
- 空状态和 Loading 状态虽然是小细节，但对用户体验影响很大
- Vuex 的购物车存在内存中意味着刷新就丢了，后续可以考虑存 localStorage
- WebSocket 前端封装需要处理好重连、心跳、断线等边界情况
- 每个新功能模块都需要同步更新路由、侧边栏、权限，容易遗漏
